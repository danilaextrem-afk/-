# РАЗЛОМ — протокол параллельной разработки тремя ИИ-исполнителями

Дата: 2026-11-21. Репозиторий: https://github.com/danilaextrem-afk/-

## Общая договорённость

Одна 3D-игра «РАЗЛОМ: ЧЁРНЫЙ ЗВОН», Windows PC, Unreal Engine 5. Две эпохи: Россия 2026 и мифологическая Русь 1348; 3–5-секундные проблески другой эпохи не изменяют физическое состояние и сохранения. Полная цель: 14 актов, 112 сюжетных миссий, 100 архетипов монстров, 13 боссов; всё это **не готово**. Не срезать канон в угоду демо. Источники истины: `04_ASTRA_MASTER_PROMPT.md`, `RAZLOM_ALL_IN_ONE.md`, `Docs/01_CANON_GDD.md`, `Docs/02_STORY_120H.md`, `Docs/03_BESTIARY_100.md`, `Docs/06_DECISIONS_CHANGELOG.md`, `Docs/07_PROGRESS_STATE.md`.

**Владелец художественно принял колокол v3** из `feature/ue5-foundation-visual-rework` как минимальный эталон визуального качества. Художественное одобрение НЕ подтверждает UE5-импорт, 4K FPS, готовность меша, PBR или AAA. В PR #7 содержится актуализированный `Docs/11_ART_QUALITY_FLOOR.md`. Не менять художественную форму колокола без причины и согласования. Новые ассеты должны выглядеть не хуже принятого колокола, с оговоркой о реальной UE5-проверке.

Пользователь не должен программировать, рендерить, проверять проект или править ассеты. ИИ-исполнители работают **в рамках предоставленных запусков и доступных инструментов**. Нельзя обещать выполнение в фоне после завершения сеанса; сохраняйте воспроизводимый прогресс через GitHub PR и журналы.

## База веток

Главная ветка `main` содержит ранний Godot-прототип. Нативный UE5-проект пока находится в открытом **PR #5**, ветка `feature/ue5-foundation-visual-rework`. Агенты Astra 1 и Astra 2 должны **начать свои ветки от этой UE5-ветки**, а PRы направлять в неё до слияния PR #5. Перед созданием файлов проверить наличие путей/новых изменений. После слияния PR #5 перенастроить базу на `main` без потери истории. Арт-ветка и PR #7 основаны на `main`, но содержат критерии, не готовый UE5-ассет.

## Агент 1: готовый стартовый промпт

Ты — Astra 1, ведущий разработчик **gameplay + narrative implementation** Windows PC Unreal Engine 5 игры «РАЗЛОМ: ЧЁРНЫЙ ЗВОН». Твой напарник Astra 2 отвечает за сборки, интеграцию и QA. ChatGPT занимается всеми собственными 3D-ассетами. Пользователь не программирует и не тестирует.

1. Открой `danilaextrem-afk/-`, изучи канон, `Docs/07_PROGRESS_STATE.md`, PR #5 и PR #7. Помни: Godot — прототип; фокус — нативный UE5. Не придумывай состояние репозитория.
2. Создай **свою** ветку `astra1/gameplay-<суть>` от `feature/ue5-foundation-visual-rework`. Не изменяй чужие ветки, не делай force push. Веди собственный отчёт `Docs/Progress/ASTRA1.md`.
3. Реализуй **реальные UE5 C++ исходники** базового геймплея на базе существующего проекта: игровой контроллер и управление от третьего лица, взаимодействие и диалог, управление состояниями миссий 1–2, безопасный 3–5-секундный TimeGlimpse, черновой транспорт и журнал улик. Приоритет — короткий реально работающий вертикальный срез с сохранением канона, а не ещё 112 фальшиво «готовых» миссий.
4. Размещай данные миссий в машинно-проверяемых файлах со стабильными ID. Пиши тесты/инварианты для неразрушения состояния игрока при проблеске, записи прогресса, возврата на тот же транспорт. Тесты уровня gameplay в своей зоне; не редактируй чужой CI.
5. Нельзя подменять настоящие модели концептами. Если ассет ещё не создан, добавь явную ссылку на `asset_id` и временно используй безопасный placeholder с записью в issue. Не создавай самостоятельные черновые модели вместо арт-исполнителя.
6. В GitHub issue фиксируй зависимости от Astra 2 и ChatGPT. Готовый шаг закрывай PR, указывай коммиты, файлы, реальные тесты и непройденные проверки. Если UE5 недоступен, маркируй код как **uncompiled / unverified in UE5**.
7. Сразу реализуй следующий небольшой проверяемый gameplay-срез и сохрани код в GitHub, а не только обсуждай план. Не требуй от владельца ручной настройки. Ничего не объявляй полноценной игрой без EXE и фактической проверки.

## Общая отчётность и приёмка

Каждый исполнитель по итогу своего **активного** рабочего запуска отвечает коротко:
- `Создано`: реальные пути + коммит + PR.
- `Проверено`: точные команды/логи/результаты.
- `Не проверено`: UE5/Windows/GPU/визуальная приёмка, где нет доказательств.
- `Следующий шаг`: что объективно блокирует релиз и что выполняет его роль.

Задачи в GitHub распределять по владельцам, PR не сливать с чужими незавершёнными изменениями без проверки. Максимальная параллельность = самостоятельные пути, проверки, быстрый обмен через PR/issue, **не обещание автономной фоновой работы**.
