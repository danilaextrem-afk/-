# Играбельный участок «Галерея Г-4»

Исходная точка — проект v0.1. Теперь в основной сцене есть открытый вход на восточной окраине (24, 0, −20). За ним пять стыкуемых секций спуска, внизу — аптечка. Предмет и положение игрока сохраняются штатной системой v1. Посёлок, склад и лес пока в блокинге.

| Параметр | Галерея Г-4 |
|---|---|
| Asset ID | RZ_ZONA_ENV_GALLERY_G4_001 |
| Исходник | tools/build_gallery.py, Python 3 + Pillow |
| Экспорт | assets/bunker/gallery.gltf, Y-up, метры |
| Геометрия секции | 494 треугольника, один меш, одна поверхность |
| Пиксельный атлас | gallery_atlas.png, 128 × 64, один материал |
| Габариты | 4,08 × 4,28 × 4 м с учётом уклона |
| Точки стыковки | Вход (0,0,0), выход (0,−1,−4) |
| Коллизии | Неподвижная треугольная сетка каждой секции |
| LOD | Включена генерация при импорте. Ручной LOD отсутствует |
| Приёмка | Импорт и проход штатной капсулой игрока в Godot 4.7.2, Linux headless |
| Два ракурса | docs/gallery/threshold.jpg, docs/gallery/return.jpg — Blender Cycles из экспортированной геометрии |
| Связанные задачи | #128, #132 |

В корневом каталоге проекта последовательно выполнить:

```sh
python3 tools/build_gallery.py
godot --headless --import
python3 tests/test_project.py
XDG_DATA_HOME="$(mktemp -d)" godot --headless --fixed-fps 60 -s tests/bunker_walk.gd
```

Последняя проверка ведёт игрока от подхода до аптечки, подбирает её, сохраняет игру, пересоздаёт сцену и возвращает игрока на поверхность. Для повторения иллюстраций используется Blender в фоновом режиме с tools/render_gallery.py. Коллизии мелких деталей можно упростить после профилирования. Приёмка на телефоне и игровой захват в Android ещё предстоят.

## Багровая деревня — улица Залесья

RZ_ZONA_ENV_ZALESYE_STREET_001, сборка окружения. Вход с западного конца дороги. Модель в метрах: 56,17 × 10,78 × 70,28 м, начало координат на дороге у точки старта. GLB содержит 18 388 треугольников и три материала. Кроме GLB используются плоскость дорожного полотна и материал неба. Атлас деталей 256 × 256, карта грунта и воды 320 × 1536, панорама 1536 × 512. Источники: tools/build_street.py, road_surface.py и storm_sky.py (NumPy, SciPy и Pillow).

На домах, ограде вдоль улицы и машине стоят простые коллизии. Провода, трава и деревья этого набора декоративны. Генерация LOD включена в импорте glTF; на устройстве уровни детализации и нагрузка прозрачной листвы ещё не профилированы. CI сохраняет два вида с камеры персонажа (village.png и porch.png). Геометрия разделена по материалам и запечена на всю улицу; при расширении карты понадобится секторное отсечение. PR #139.

## Залесье — отделение связи

Ревизия RZ_ZONA_ENV_ZALESYE_STREET_002 в PR #166 продолжает игровой вариант #143. Передний план включает отделение связи с навесом и окном выдачи, машину с багажником и пять берёз. Дом использует общую сетку улицы, его корпус и машина имеют отдельные простые коллизии. Стол выдачи и полки видны снаружи. Геометрия отделения занимает примерно 7,1 × 5,35 × 5,8 м до поворота. Общая сетка street.glb содержит 20 608 треугольников, 3 материала, атлас 1024 × 1024. На загрузке применяется прежний фильтр 136 треугольников башни. Импорт glTF запрашивает LOD; исходная сцена пересобирает поверхности при фильтрации, поэтому сохранение LOD в итоговой сетке не подтверждено.

tools/build_street.py собирает сетку и атлас, tools/road_surface.py собирает карту грунта с маской воды 320 × 1536. В tools/sources/zalesye_surfaces.jpg сохранён исходный лист сгенерированных диффузных фактур. Локально проверены импорт в Godot 4.7.2, путь от старта, загрузка сохранения в бункере, обычный проход через КПП и обработка трёх одновременных касаний. CI captures/village.png, post_office.png и porch.png сняты игровой камерой. Android debug собирается отдельно в CI. Замер на телефоне предстоит.
