# Сервер поиска Realtor AI

```sh
cd realtor/search
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export REALTOR_SEARCH_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
uvicorn service:app --host 127.0.0.1 --port 8080
```

Запускайте одним процессом на постоянном хосте, с постоянным диском для `REALTOR_DB` и HTTPS перед сервером. Токен выдаётся одному пользователю или одному доверенному пространству. В Android сохраните HTTPS-адрес и токен в «Настройки → Поиск по площадкам». Отправьте запрос в чате, затем включите мониторинг. Сервер проверяет сохранённый запрос раз в 30 минут, приложение переносит события при своём фоновом запуске. Android самостоятельно определяет время доставки уведомлений. Первое обнаружение объекта считается новым. Продажа и аренда обрабатываются отдельно, рынок и тип продавца учитываются при наличии подтверждённых полей.

Администратор настраивает `REALTOR_SOURCES` с ключами `avito,cian,domclick,yandex,m2,developer`. Для каждого задайте `feed` (разрешённая выгрузка HTTPS или внутренний авторизованный API), `format` (`yrl` или `json`), при необходимости `token_env` (имя переменной токена). Для застройщика дополнительно укажите `domain` и `path` (регулярное выражение прямой карточки). JSON принимает массив или `{"offers":[...]}` с полями url, title, address, region, locality, photos, price, currency, area, rooms, deal, market, seller, status и при наличии expires_at. Площадки без разрешённого доступа возвращают явный статус. XML-фид размещения не даёт доступа ко всему каталогу площадки.

Groq использует `GROQ_API_KEY` для разбора свободного текста в серверном API. Без ключа либо при сбое применяется обычный разбор. Android использует свои существующие настройки облачного чата и передаёт серверу фильтры. SearXNG использует `SEARXNG_URL` с JSON API, Firecrawl использует `FIRECRAWL_API_KEY`. Поисковые провайдеры поставляют ссылки, которые сами по себе не считаются объявлениями.

Для домена, разрешившего автоматическую обработку, можно включить `allow_page_read` и передать `pages` с прямыми URL или воспользоваться настроенным индексом. Укажите `deal`, `market` и при необходимости `seller` только для однородного, явно известного раздела. Проверяются robots.txt, HTTP-ответ, наличие в структурированных данных и полнота карточки. Пустой или запрещающий robots.txt не следует заменять прокси-обходом. Опционально `renderer=playwright` или `renderer=crawl4ai` после установки `requirements-browser.txt` и Chromium. Они получают фактологические данные из разрешённой страницы, без решения CAPTCHA и обхода ограничений доступа. Для регулярно меняющихся каталогов предпочтительна разрешённая выгрузка.
