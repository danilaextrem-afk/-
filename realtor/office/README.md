# Общая база Realtor AI

Один экземпляр обслуживает один офис. Сервис использует Python 3.11+ и SQLite, без дополнительных пакетов. Android-клиент открывается в «Профиль → Общая база офиса». Локальная CRM продолжает работать без сервера.

## Запуск

На сервере с закрытым доступом к файлам базы выпустите учётные записи через CLI. Выдавайте токены сотрудникам через защищённый канал.

```bash
cd realtor/office
python3 office.py --db /var/lib/realtor/office.sqlite3 issue broker1 'Риелтор' agent
python3 office.py --db /var/lib/realtor/office.sqlite3 issue lead1 'Руководитель' manager
python3 office.py --db /var/lib/realtor/office.sqlite3 serve --host 127.0.0.1 --port 8443
```

Для доступа со смартфона поставьте перед loopback-сервисом HTTPS-прокси с доверенным сертификатом, ограничением соединений и таймаутами. Прямой запуск с TLS принимает `--cert` и `--key`; клиент проверяет сертификат и отказывается отправлять токен через HTTP или перенаправления. Храните SQLite на зашифрованном томе и создавайте согласованный снимок командой `backup`. Файл базы, ключи сертификата и токены относятся к данным офиса.

Повторный `issue` меняет токен сотрудника и сохраняет его назначения. `revoke <id>` немедленно закрывает доступ. Администрирование учётных записей выполняется локально на сервере. Публичной регистрации нет.

## Резервная копия

```bash
python3 office.py --db /var/lib/realtor/office.sqlite3 backup /var/lib/realtor/backups/office-001.sqlite3
```

Команда проверяет целостность SQLite и отказывается перезаписывать существующий файл. Для тестового восстановления запустите отдельный loopback-экземпляр с копией снимка. Проверьте вход сотрудника, назначенные заявки и журнал, прежде чем переключать действующий сервис.

## Возможности

- Сотрудники офиса читают общие карточки недвижимости.
- Риелтор видит только назначенные ему заявки покупателей. Руководитель и администратор видят все заявки и назначают ответственного.
- Пользователь выбирает запись и явно подтверждает передачу. Телефоны, переписка, личные заметки и токены платформ не входят в схему обмена.
- Обновления проверяют ревизию. При конфликте Android просит обновить список. Локальная запись сохраняется отдельно.
- Сервер фиксирует создание, редактирование, перераспределение, удаление и операции с доступом.

В разделе «Сделки» выберите покупателя и объект из общей базы. Сделка наследует доступ и ответственного из заявки. При переназначении заявки сервер в одной транзакции меняет ответственного по связанным сделкам, обновляет ревизии и дополняет журнал.

Этапы сделки: согласование, показ, задаток, закрытие. Открытую сделку можно отменить. При закрытии указываются подтверждённая цена и комиссия. Запись сумм не проводит платежи. Связанные карточки и завершённые сделки сохраняются для истории.

Обновите сервер до версии с маршрутом `/v1/deals` перед использованием этого раздела на Android. Существующие записи сохраняются. Финансовый кабинет и автоматическое рекламное финансирование требуют отдельной реализации.

```bash
python3 -m unittest -v
```

## Размещение вторичных квартир через фид Яндекс Недвижимости

Сгенерируйте секрет URL через `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'` и передайте его процессу сервиса как `REALTOR_YANDEX_FEED_KEY`. Добавьте в корпоративном кабинете Яндекс Недвижимости адрес `https://<office-host>/feeds/yandex/<key>`. Настройте HTTPS-прокси без записи этого пути и его секрета в журналы. Секрет передаётся только уполномоченному администратору и предназначен для доступа площадки к публичным материалам объявления.

В Android администратор включает передачу и задаёт лимит активных предложений в «Общая база офиса → Корпоративное размещение». Назначенный риелтор подтверждает согласие собственника и права на материалы, указывает публичный телефон агента и ссылки на разрешённые фотографии, затем добавляет объект в фид. Повтор операции с устаревшей ревизией отклоняется. Реквизиты согласия не попадают в XML.

Изменение цены в общей базе обновляет существующее предложение под тем же идентификатором. Изменение адреса, площади, комнат или сегмента требует повторного согласования. Закрытие сделки, подтверждённое ответственным за объект или руководителем, убирает объект из фида в той же транзакции. Ручное снятие доступно в карточке. Пауза офиса возвращает пустой фид и сохраняет очередь для последующего возобновления.

Статус в Android отражает состояние фида. Подтверждение модерации и публикации проверяется в кабинете площадки. Корпоративный лимит здесь измеряется в объектах. Денежный баланс, списания и покупки продвижения требуют разрешённой биллинговой интеграции.

## Отчёт для собственника

В карточке объекта в общей базе откройте «Отчёт собственнику». Ответственный риелтор или руководитель может внести подтверждённые просмотры, обращения и рекомендации. Пустые счётчики видны как «Нет данных». Цена и состояние передачи в фид берутся из общей базы при каждом открытии отчёта.

С согласия собственника создайте ссылку и отправьте её через системное меню Android. Ссылка даёт доступ к одному объекту на 30 дней. Новая ссылка заменяет предыдущую. Доступ можно отозвать вручную. Он также закрывается при удалении или переназначении объекта и при отзыве доступа сотрудника, выдавшего ссылку.

Для работы пропустите через HTTPS-прокси пути `/owner` и `/owner/*`. Секрет ссылки находится во фрагменте URL, а браузер отправляет его только в заголовке авторизации запроса отчёта. Не включайте этот заголовок в журналы прокси. При восстановлении устаревшего снимка перед открытием доступа удалите прежние ссылки командой SQL `DELETE FROM owner_access;` и выпустите нужные ссылки заново.

## Корпоративный фид Циана

Для вторичных квартир задайте отдельный секрет `REALTOR_CIAN_FEED_KEY` и укажите в выделенном фиде кабинета Циана адрес `https://<office-host>/feeds/cian/<key>`. Не заменяйте этим адресом действующий фид с другими объектами. Исключите путь и секрет из журналов HTTPS-прокси.

В Android откройте «Общая база офиса → Корпоративное размещение → Циан». Администратор отдельно включает канал и задаёт лимит. Ответственный подтверждает разрешение собственника и права на фотографии. Для Циана также нужны этаж дома и описание от 15 символов без `&`. Фид передаёт `noPromotion`. Тарифы самого размещения определяет корпоративный кабинет.

Цена обновляется с тем же идентификатором. Закрытие сделки или ручной отзыв исключают объект из соответствующего фида. Подтверждение модерации, появления и снятия на площадке проверяется в Циане.
